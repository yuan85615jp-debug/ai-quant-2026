# AI 量化课程核心知识点详解（内部文档）

> 来源：2025年1月「AI量化入门：打造本地量化知识库 & 股票量化开发」课程  
> 提炼与扩展时间：2026年  
> 目标：把课程中真正跨时代、可迁移的底层思维沉淀为可复用的内部知识

---

## 1. 本地优先的 AI 投研架构思维

**核心观点**  
把大模型、向量库、知识库尽量部署在本地或私有环境，数据不出域。

**为什么重要**  
- 机构有严格的数据合规与隐私要求  
- 个人研究者不想把交易思路与持仓暴露给第三方  
- 本地推理延迟更低，适合盘中辅助决策  

**实践要点**  
- 使用 Ollama / Llama.cpp / vLLM 等本地推理引擎  
- 向量库优先选 PGVector、Chroma、Qdrant（可私有化）  
- API 层做统一抽象，方便在「本地模型」与「云端强模型」之间切换  

**常见误区**  
只追求模型参数量，而忽略数据安全与系统可维护性。

## 2. RAG + 专业知识库是量化 AI 的正确打开方式

**核心观点**  
单纯让 LLM 自由发挥容易产生幻觉。把策略文档、交易日志、研报、历史案例做成向量知识库，再通过检索增强生成（RAG），才能形成稳定、可追溯的输出。

**为什么重要**  
- 量化决策需要可解释性与可复现性  
- 专业知识更新快，知识库比微调更灵活  
- 可以把「人的经验」持续沉淀进系统  

**实践要点**  
- 文档切分策略要针对金融文本优化（按章节、按策略逻辑切）  
- 使用高质量 Embedding 模型  
- 加入重排序（Rerank）提升检索精度  
- 记录每次回答引用了哪些文档片段，便于审计  

---

## 3. 多智能体角色分工 > 单一全能模型

**核心观点**  
让不同风险偏好、不同时间视角的「交易员智能体」各自独立分析，再由决策者综合，能显著降低单一模型的偏差与幻觉。

**为什么重要**  
- 真实机构也是投研、交易、风控多方制衡  
- 不同角色天然形成「对抗样本」，暴露盲点  
- 便于后续针对单一角色做专项优化  

**实践要点**  
- 角色提示词要差异化足够大（机构 vs 激进 vs 资深）  
- 强制结构化输出，方便程序化比较与综合  
- 决策者提示词要明确「一致性如何影响仓位」与「风险一票否决权」  

---

## 4. 结构化输出是生产级系统的生命线

**核心观点**  
所有 LLM 输出必须能被程序可靠解析（JSON + Schema 校验）。否则无法接入下单、风控、回测、通知等后续环节。

**为什么重要**  
- 非结构化文本无法自动化  
- 模型偶尔会「发挥」，必须用 Schema 兜底  
- 便于日志、评估、A/B 测试  

**实践要点**  
- 优先使用 `response_format={"type": "json_object"}` 或工具调用  
- 用 Pydantic / Zod 等做运行时校验  
- 校验失败时触发重试或降级策略

## 5. 截面思维比纯时间序列更接近机构做法

**核心观点**  
在同一时间点对全市场（或成分股）计算因子并横向比较，比只盯着单只股票的历史走势，更容易发现相对强弱与拥挤度。

**为什么重要**  
- 机构资金容量大，必须考虑相对价值与流动性  
- 截面因子天然适合选股与组合构建  
- 可与时间序列信号结合使用  

**实践要点**  
- 因子计算要处理停牌、ST、次新股等特殊情况  
- 注意行业中性、市值中性等处理  
- LLM 适合做「因子解读」与「异常值解释」，而非直接替代因子计算  

---

## 6. 提示词工程的本质是「把人类专家思维编码」

**核心观点**  
好的提示词不是华丽的修辞，而是把专家的决策框架、优先级、禁忌条件显式地写清楚，让模型可复现、可调参。

**为什么重要**  
- 把「只可意会」的交易感觉变成可执行规则  
- 方便团队协作与版本迭代  
- 降低对单一「提示词高手」的依赖  

**实践要点**  
- 分离 System（角色与原则）与 User（具体数据）  
- 明确输出格式与必答字段  
- 加入「自我检查」步骤（例如利弗莫尔条件是否同时满足）  

---

## 7. 数据 → 特征 → LLM 解读 的标准 Pipeline

**核心观点**  
可靠的数据源 → 技术/基本面/另类特征工程 → 结构化喂给 LLM → 可执行建议。跳过特征工程直接把原始 K 线丢给模型，效果通常很差。

**为什么重要**  
- LLM 擅长推理与总结，不擅长高精度数值计算  
- 特征工程是把领域知识注入系统的关键步骤  
- 便于后续做归因与回测  

**实践要点**  
- 技术指标计算用成熟库（pandas-ta、TA-Lib）  
- 把特征与原始数据一起结构化传给模型  
- 记录特征版本，方便复现实验  

---

## 8. 自动化闭环比单次分析更有价值

**核心观点**  
「能跑一次的分析脚本」只是玩具；「每天自动跑完并推送结果」才是真正可用的工具。

**为什么重要**  
- 人的注意力有限，系统必须主动服务人  
- 形成闭环后才能积累真实使用数据，反哺优化  
- 是从研究走向生产的必经之路  

**实践要点**  
- 使用定时任务（cron / APScheduler / 系统服务）  
- 结果通过邮件、企业微信、Telegram 等推送  
- 失败时要有告警，避免静默失败  

---

## 9. 风控与仓位管理必须被写进提示词与输出结构

**核心观点**  
任何没有明确止损、仓位、失效条件的交易建议，都不应该进入实盘流程。

**为什么重要**  
- 交易的本质是风险管理和概率游戏  
- LLM 容易给出「看起来合理但无法执行」的建议  
- 强制输出风控字段，是对使用者的保护  

**实践要点**  
- 在 System Prompt 中明确要求输出止损、仓位、失效条件  
- 在 Schema 中把这些字段设为必填或强烈建议  
- 决策者综合时，对缺少风控信息的意见降权  

---

## 10. 系统可观测性与可迭代性

**核心观点**  
日志、中间结果落盘、决策溯源、不同提示词/模型的 A/B 测试，是系统长期进化的基础。

**为什么重要**  
- 没有数据就无法科学改进  
- 出问题时能快速定位是数据问题、提示词问题还是模型问题  
- 支持「用真实交易反馈反哺提示词与知识库」的正向循环  

**实践要点**  
- 每次分析保存：输入数据、各交易员原始输出、最终决策、时间戳  
- 定期回顾「预测 vs 实际」  
- 把有效的改进沉淀回知识库或提示词版本库  

---

## 总结：这 10 点如何指导系统设计

| 知识点 | 对应系统设计原则 |
|--------|------------------|
| 1 本地优先 | 架构默认支持私有化部署 |
| 2 RAG 知识库 | 核心能力之一，而非可选功能 |
| 3 多智能体 | 分析层采用多角色并行 + 决策者综合 |
| 4 结构化输出 | 全链路强制 Schema |
| 5 截面思维 | 选股模块独立，支持全市场扫描 |
| 6 提示词编码 | 提示词版本化、可测试 |
| 7 标准 Pipeline | 数据层与推理层严格分离 |
| 8 自动化闭环 | 从第一天就考虑定时与通知 |
| 9 风控内建 | 输出结构强制包含风控字段 |
| 10 可观测可迭代 | 日志与评估不是后加的，而是内建的 |
